# 风险模型

用风险来决定测试深度。

## P0

最高风险：

- 资金流转
- 鉴权和权限
- 关键状态迁移
- 生产可用性
- 数据损坏或数据丢失

建议深度：

- 定向自动化测试
- 集成验证
- 尽可能在准生产或高保真环境验收

## P1

重要工作流风险：

- 共享集成
- 多界面一致性
- 业务工作流连续性

建议深度：

- 模块测试
- 选择性集成检查
- 定向验收验证

## P2

局部且较低风险问题：

- 孤立 UI 行为
- 展示逻辑
- 局部组件变更

建议深度：

- 本地测试
- 类型检查或 lint
- 抽样人工验证

## 提升测试深度的信号

出现以下情况时，应提高测试深度：

- 涉及多个系统
- 改动影响事实源或主状态源
- 回滚成本高
- 用户很难准确描述失败模式
